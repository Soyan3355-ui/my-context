## トークンの節約（2026-11-06 そーやんの依頼。案 A：運用ルールのみ）

見回りの中身（メール・LINE・カードの確認、報告）は省かず、読み方と書き方を軽くする。
1. **たまった通知は最新の1件だけ処理する**：再起動などで同じ種類の通知が複数たまっていたら、最新の1件だけ回す。古い回は、Notion の進捗ログに「まとめて確認（N回分）」と1行だけ残し、1回ずつやり直さない
2. **差分だけ読む**：
   - LINE のシート：まず日時の列（A 列）だけを読み、`status/now.mail.checkedAt` より新しい行があるときだけ、その行の本文（B〜D 列）を読む。広い範囲を本文ごと読まない
   - Gmail：`search_threads` の件名・送信者・日付で判断する。`get_thread` で本文を開くのは、返事や対応が要りそうなものだけ（自動通知・宣伝・SNS は開かない）
   - 例外カード・つぶやき・ネタ会議：前回の `lastRunAt` 以降のものだけを `limit` 小さめで読む。ファイルに保存して全文を読み込まない（`out_dir` を使い、必要な項目だけ python などで取り出す）
   - freee：前回の `asOf` の翌日からの明細だけを読む。請求書の一覧など大きな結果は、必要なときだけ
3. **大きい読み取りをしない**：画面の HTML（`village-live.html` など）は、全体を読まず、リポジトリのコピーを Grep して必要な行だけ読む。Artifact の `read` は、コメントの確認だけなら `ArtifactComments` を使う。ツールの説明が長いもの（Notion の検索など）は、1つのセッションで読み込む回数を減らす
4. **サブエージェントは軽いモデルで**：記録監査（シーサー）・検収（鎧さん）・仕事さがしは、`model: haiku` で起動する。内容が重要で、判断が難しいときだけ、既定のモデルにする
5. **新着なしの回は書き込みを最小に**：ダイジェスト更新の回で新着がなければ、`status/now` の `lastRunAt`・`updatedAt`・`mail.checkedAt` だけを更新する（`digest` は書き直さない）。Notion の進捗ログは、朝・夕・週次の回と、何かが動いた回だけに書く
6. 上のどれも、メール・LINE・カレンダーの確認そのものを省く理由にはならない（`メールの確認` の「省略しない」はそのまま）
