# /jigyo-update 〈事業名〉

事業ページの細かい中身（内容・回数・価格・日程・体制・コンセプト）を、実際の動きに追いつかせるための手順。

## 1. 対象を決める
- `notion-map.md` の「事業ページ台帳」から対象の事業を探す。メインページ・情報源・公開範囲を確認する。
- 台帳にない事業なら、そーやんに「メインページはどれにする？」と確認して台帳に追記する。

## 2. 最近の情報を集める（最終更新日より後のもの）
メインページ冒頭の「📌 現状サマリー」の最終更新日を起点にする（なければ直近60日）。
- Notion：ミーティング議事録 DB で事業名・関連語を検索（AI 会議メモの要約・アクションアイテムを優先）
- Google ドライブ：事業名で検索（LP 原稿・スライド・告知文など）
- Gmail：事業名で検索（参加者への案内・会議アセットの通知など）
- 会話：このセッションでそーやんが話したこと
- 日記は**読むだけ**。内容をそのままページに書き写さない（公開範囲が違うため）

## 3. ズレを洗い出して、そーやんに見せる
メインページと子ページを読み、次の形で短く一覧にする。**この時点では Notion を書き換えない。**

```
### 変わったこと（ページが古い）
- [ページ名] 今の記述 → 実際（根拠：資料名・日付）
### 新しく決まったこと（ページにまだない）
- 内容（根拠）
### 迷うこと（どれが最新かわからない）
- 資料Aでは〇〇、資料Bでは△△ → どっち？
```

## 4. OK をもらってから反映する
- 既存の文章は `update_content` で該当箇所だけ直す。ページ全体の置き換えやブロックの削除はしない。
- メインページ冒頭の「📌 現状サマリー」を更新する（なければ作る）：

```
<callout icon="📌" color="blue_bg">
	**現状サマリー**（最終更新：YYYY-MM-DD）
	- いまの形：…
	- 直近の予定：…
	- 決まったこと：…
	- 検討中：…
</callout>
```

- ページ末尾の「🕰 変更履歴」に1行追記する（なければ作る）：`- YYYY-MM-DD：〇〇を△△に変更（根拠：…）`
- 古い構想ページで、今の実情と大きく違うものは、冒頭に「※YYYY-MM-DD 時点の整理です」の注記を入れる（中身は消さない）。

## 5. 公開範囲を確認する
- 台帳の公開範囲が「さやさんにも見える」ページに、お金・人事・家族・日記の内容を書かない。
- 迷ったら書かずに、そーやんに聞く。

## 6. 記録する
- 同期ログ DB に1行追加（タイトル `YYYY-MM-DD 事業更新：〈事業名〉`、種別「セッション同期」）。
- `mkdir -p .claude/state && date +%s > .claude/state/last_notion_sync` を実行する。
- `notion-map.md` の台帳の「最終更新」を更新してコミット・push する。
