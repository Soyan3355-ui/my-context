# ドリーミング（夜間の自動改善）設計案

状態: **設計案（未稼働）**。稼働にはそーやんの承認が必要。承認後に `standards/feedback-targets.md` へ登録する。

## 狙い
夜間などの空き時間に、セッション履歴の見直し（`standards/session-review.md`）を自動で回し、改善案をPRとして朝に届ける。

## 仕様案（基準書 GOV-02・第13章に沿う）

| 項目 | 内容 |
|---|---|
| 種類 | Claude Code Routines（定期実行） |
| 頻度 | 週1回（日曜 23:00 JST 頃）。週次リサーチ（月曜 06:52 JST）と重ならない時間にする |
| 入力 | 直近の履歴、`CLAUDE.md`、スキル一覧、`standards/session-review-log/` |
| 処理 | 抽出プロンプトで「2回以上の繰り返し」を洗い出し、仕分けて差分案を作る |
| 出力 | 改善案のPR（ブランチ `dreaming/YYYY-MM-DD`）と、`session-review-log/` の記録 |
| 自律度 | L1。提案まで。マージ・本番反映はしない |
| outcome_link | 繰り返しの指摘が減り、そーやんの手戻り時間が減る |

## 安全策
- 変更対象は `CLAUDE.md`・スキル・`acceptance/` の差分案に限る。権限設定とフックは対象外（`GOV-02`）。
- 1回のPRは最大5件。多いときは優先度順に持ち越す。
- 指摘がなければ「変更なし」を記録して終わる（`GOV-06`）。
- 履歴の引用は短く、個人情報・機密は伏せる。

## 効果の見方（四半期に1回）
- 同じ指摘の再発回数が減っているか。
- PRの採用率が低いなら、抽出の基準を見直す。
- ルールが増えすぎていたら、古いものを削る。

## 決定事項
- 頻度は週1（2026-10-05 にそーやんが決定）。
