# セッション履歴レビュー（ハーネス改善の手順）

過去のセッション履歴から「繰り返しの指摘」と「同じ失敗」を抜き出し、スキル・テスト・CLAUDE.md に反映するための手順書。

- **目的:** 同じ指摘を何度もしなくて済む状態を作り、本業の時間を増やす。
- **頻度:** 手動なら月1回を目安。週1の自動実行は `standards/dreaming-design.md` の設計案に沿って移す。
- **自律度:** L1（提案まで）。反映はPRで、そーやんが承認する（`GOV-02`）。

## 手順

1. **履歴を集める** — 対象期間（例: 直近30日）のセッション履歴を用意する。
2. **抽出する** — 下のプロンプトをClaude Codeに渡す。
3. **仕分ける** — 抽出結果を3つの反映先に振り分ける（手順ミス→スキル、判定ミス→テスト、方針→CLAUDE.md）。
4. **反映する** — 差分をPRにする。根拠（セッション・発言）を本文に引用する。
5. **記録する** — `standards/session-review-log/YYYY-MM-DD.md` に結果を残す。指摘がなくても「変更なし」と残す。

## 抽出プロンプト

```
対象期間のセッション履歴を読み、次を洗い出してください。

1. 私が同じ趣旨の修正・指示を2回以上繰り返した箇所
2. あなたが同じ手順で繰り返し失敗した箇所
3. 私が「違う」「そうじゃない」と言った直後の流れ

それぞれについて、次の形式で出力してください。
- 事象（1行）／回数／根拠となる発言の引用
- 原因の見立て（手順・判定・方針のどれか）
- 反映先の提案（スキル名／テスト／CLAUDE.md）と、具体的な差分案

制約:
- 1回きりの指摘は「様子見」として分け、反映案にしない。
- 反映案は最大5件。優先度は「繰り返し回数 × 手戻りの大きさ」で決める。
- ファイルは変更せず、提案だけを出す。
```

## 仕分けの目安

| 事象 | 反映先 |
|---|---|
| 手順の抜け・順序ミス | スキルファイルの手順を修正 |
| 出来上がりのチェック漏れ | テスト・`acceptance/` に検証項目を追加 |
| 口調・好み・判断軸 | `CLAUDE.md`（または `working_style.md`） |
| 既存ルールとの矛盾 | 矛盾を提示し、そーやんに判断を仰ぐ |

## 注意
- 反映しすぎるとルールが肥大化し、かえって守られなくなる。**2回以上の繰り返し**だけを対象にする。
- 個人情報や機密を、ログや引用にそのまま残さない。
