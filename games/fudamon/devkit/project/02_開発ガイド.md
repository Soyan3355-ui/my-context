# 封札モンスターズ 開発キット

ブラウザRPG「封札モンスターズ」の開発で使った情報を、次のゲーム開発でそのまま再利用できるようにまとめたフォルダです。
コード、ドット絵の作り方、AIへの指示文、品質チェックの道具、バランス調整の方法をすべて含みます。

- リポジトリ: `Soyan3355-ui/my-context`（ブランチ `claude/gifted-thompson-g9s4zw`）
- ゲーム本体: `games/fudamon/index.html`（ブラウザで開くだけで動きます）
- 公開版: https://claude.ai/artifact/1C6nmfWPzTG9h5cTDWRF5o

---

## 1. フォルダ構成

| 場所 | 中身 |
|---|---|
| `../index.html` | 画面の骨組みとCSSのすべて |

| `../js/engine.js` | セーブ、ステータス計算、経験値曲線、入力、マップ描画 |
| `../js/ui.js` | 会話、メニュー、ショップ、カード詳細、進化 |
| `../js/battle.js` | バトル、封印（捕獲）、演出 |
| `../js/story.js` / `../js/chapter2.js` | ストーリー、NPC、試練、ライバル、エンディング |
| `../js/pixel.js` | フィールドのタイル、キャラクターのドット絵 |
| `../js/pixkit.js` | **モンスターのドット絵を描く道具一式（再利用の要）** |
| `../js/pixmon_1〜7.js` | モンスター60体の描画コード |
| `../js/audio.js` | BGM12曲と効果音32種（すべてプログラムで生成） |
| `PIXMON_STYLE.md` | **モンスタードット絵の品質基準（英語・決定版）** |
| `prompts/` | AI担当者への指示文（原文） |
| `preview/` | ドット絵の確認ページと撮影スクリプト |
| `qa/` | 自動プレイテストとバランスシミュレーター |
| `sheets/` | 完成品の見本画像（品質の基準として使う） |
| `refs/` | 参考画像の置き場所（著作物のためリポジトリには含めない） |

## 2. 技術の方針

- 素のHTMLとJavaScriptのみ。フレームワークもビルドも不要で、ファイルを開くだけで動く
- 画像ファイルを一切使わない。ドット絵、BGM、効果音はすべてコードで生成する
  - 利点: 著作権の心配がない、容量が小さい、AIが直接編集できる
- フィールドは内部解像度 256×176 を整数倍に拡大（ドットがにじまない）
- モンスターは 80×80 のキャンバスに描き、PNGに変換してキャッシュ（60体で約0.3〜0.6秒）
- セーブはブラウザ保存（localStorage）で3枠

## 3. ドット絵を同じ品質で再現する方法

### 3-1. 完成品の見本

- `sheets/monsters_all_2x.png`: 全60体の一覧（品質の基準）
- `sheets/reference_six_detail.png`: 最初に作った基準の6体（6倍・3倍・1倍）
- `sheets/screen_*.png`: タイトル、フィールド、森、バトルの画面

### 3-2. 品質を決めているルール（要点）

詳細は `PIXMON_STYLE.md` を必ず読むこと。要点は次のとおりです。

1. **テイストだけ真似る**: SFC時代のドラクエのモンスターが目標。ただし既存モンスターに似たデザインは禁止。似てきたら色ではなくシルエットを変える
2. **ドットの密度**: 大きな面は必ず質感（うろこ、毛、樹皮、石、羽、布）で埋める。平坦な塗りを残さない
3. **陰影**: 1色につき7段階の色。影は紫・青寄り、ハイライトは黄色寄りにずらす。左上から光を当てる
4. **輪郭**: 1ドットの黒に近い線で全体を囲む。素材が違う部品の境目にも黒い線を入れる
5. **目は小さく鋭く**: ぎょろ目はゲーム全体で1〜2体だけ。愛嬌は口、舌、ポーズで出す
6. **1体につき1つのアイデアと1つのギャグ**: 例「しっぽが焚き火で、舌がしまえない狐」
7. **シルエットはでこぼこに**: 毛のふさ、トゲ、爪、小道具。つるんとした丸や四角の体は禁止
8. **大きさはレア度で決める**: C 40〜50px、R 46〜58px、SR 58〜72px、UR 最大76px
9. **方向性をはっきり分ける**: かっこいい系、おどろおどろしい系、かわいい系、癒し系

### 3-3. 作る手順

1. `PIXMON_STYLE.md` と `../js/pixmon_1.js`（基準の6体）を読む
2. `prompts/PIXMON_TASK.md` の形式で、1体ずつ「コンセプト、ギャグ、色、大きさ」を決める
3. `pixkit` の部品（楕円、管、トゲ、目、口、歯、質感、毛のふさ）で描く
4. 確認ページで撮影して見比べる
   ```
   node devkit/preview/shot.js sheet.html "sheet=1" all.png        # 全体一覧
   node devkit/preview/shot.js sheet.html "id=1,4" detail.png      # 6倍・3倍・1倍
   node devkit/preview/shot.js compare.html "s=4&id=1" cmp.png     # 参考画像と同じ倍率で比較
   ```
5. 参考画像と**同じ整数倍率**で並べ、差分リスト（密度、陰影、目、シルエット、色）を書いて直す。これを最低3周
6. 見本を人に見せる前に、必ず自分で参考と比較してから出す

### 3-4. 別のゲームで使う場合

- `js/pixkit.js` をコピーすれば、どのゲームでも同じ品質のモンスターやキャラを描ける
- 色の組（ランプ）は `PIXKIT.addRamp(名前, [5色])` で追加できる
- フィールドのタイルとキャラクターは `js/pixel.js` の書き方を真似る（16×16タイル、キャラ16×21、4方向×3コマ）

## 4. 開発の進め方（全ジャンル共通）

1. **絵柄の見本を最初に作り、OKが出てから実装する**（今回は絵柄を3回作り直した）
2. **最初から最後まで遊べる最小版を作り、そこから広げる**
3. **役割ごとにAI担当を分ける**: ゲームデザイン、ドット絵、サウンド、QA。指示文の実例は `prompts/SUBAGENT_PROMPTS.md`
4. **品質チェックを繰り返す**: 作る → 自動テスト → レビュー → 修正 を最低2周。QAは問題を「重大／中／軽微」に分けて報告
5. **数値は1か所にまとめる**: `data.js` に集約したので、進化レベルの変更や取り消しが一瞬でできた
6. **バランスはシミュレーションで決める**: 勘ではなく、ゲームと同じ計算式で勝率を出す
7. **区切りごとにコミットし、遊べるリンクを公開する**
8. **報告は「変えたこと」「確認したこと」「未確認のこと」を分ける**

## 5. 品質チェックの道具

Playwright（ブラウザ自動操作）で実際にゲームを動かして確認します。

```
cd games/fudamon
node devkit/qa/flow.js        # 最初から通しプレイ
node devkit/qa/seal.js        # 封印（捕獲）演出
node devkit/qa/t_evo2.js      # 進化
node devkit/qa/t_rival.js     # ライバル乱入
node devkit/qa/t_slot.js      # セーブ枠
node devkit/qa/balance_sim.js # バトルの勝率シミュレーション（games/fudamon で実行）
```

- `qa/lib.js` が共通の土台です。新しいテストはこれを使うと数行で書けます
- 撮影した画面は `qa/out/` に保存されます
- 合格の条件は「ページのエラーがゼロ」と「画面の目視確認」

## 6. バランスの数値（調整の基準）

| 項目 | 値 |
|---|---|
| 次のレベルまでの経験値 | `12 + レベル² × 0.8` |
| 経験値の補正 | 相手と自分のレベル比で 0.4〜1.3 倍 |
| 進化に必要なレベル | C 14 / R 20 / SR 26 / UR 40 |
| 進化に必要な同じカード | C 2枚 / R 1枚 / SR 1枚 / UR 0枚 |
| 進化後の能力 | 1.35倍、レア度が1段階上がる |
| キラ・金カードの能力 | 通常の1.05倍 / 1.10倍 |
| 封印率の上昇 | 失敗するたびに +8%（最大 +40%） |
| 技の回数（PP） | 25 / 20 / 10（URの大技は8） |
| 出現レベル | 道 2〜6、草原 8〜12、谷 12〜16、山 16〜20、森 20〜25 |
| 最初の試練（イワオ） | Lv12・13・15。推奨Lv15で勝率 約70〜80% |
| 伝説 | Lv32、Lv38。封印するまで再挑戦できる |

## 7. 依頼の履歴と学び

| 依頼 | 学び |
|---|---|
| かわいすぎる → 遊戯王風 → ドット絵 → ドラクエモンスターズ風 | 絵柄は最初に参考画像で決める |
| 顔が潰れて見える | 1倍の大きさでも顔が読めるかを必ず確認する |
| 参考と比べてから見せて | 自己チェックを指示すると品質が大きく上がる |
| 方向性をはっきり分けて、癒し系も | キャラ一覧に「系統」の列を作っておく |
| 行商人のカードパックはやめて | 収集ゲームでは「お金で集められる」仕組みが楽しさを壊す |
| 手放すを間違えないように | 取り返しのつかない操作は二重確認、初期選択は「やめる」 |
| イワオをLv15くらいに | 難しさは「推奨レベル」と「勝率」で指定すると伝わりやすい |
| 進化レベル+5 → 元に戻す | 数値を1か所にまとめ、変更を1コミットにしておくと戻しやすい |
